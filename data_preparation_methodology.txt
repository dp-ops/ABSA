DATA PREPARATION METHODOLOGY

1. OVERVIEW

The data preparation pipeline was designed to process Greek language review data for aspect-based sentiment analysis using BERT-based models. The methodology encompasses raw data preprocessing, aspect detection, sentiment extraction, noise reduction, and optional data augmentation to address class imbalance issues.

2. INPUT DATA STRUCTURE

The raw dataset consisted of a CSV file (reviews_NoDuplicates_TrainTest.csv) containing Greek language product reviews with the following structure:

2.1 Text Content Columns:
- 'reviews': Original Greek review text
- 'text_lemma': Lemmatized version of the review text

2.2 Aspect Rating Columns:
Eight predefined aspect categories with numerical sentiment ratings:
- "Ποιότητα κλήσης" (Call Quality)
- "Φωτογραφίες" (Photos)
- "Καταγραφή Video" (Video Recording)
- "Ταχύτητα" (Speed)
- "Ανάλυση οθόνης" (Screen Resolution)
- "Μπαταρία" (Battery)
- "Σχέση ποιότητας τιμής" (Price-Quality Ratio)
- "Μουσική" (Music)

Each aspect was rated using a three-point scale:
- '-1': Negative sentiment
- '0': Neutral sentiment
- '1': Positive sentiment
- '-': No rating/Not applicable (excluded from processing)

2.3 Data Split Column:
- 'type': Indicates data split designation ('train' or 'test')

3. TEXT PREPROCESSING

3.1 Tokenization Framework:
The preprocessing pipeline utilized the nlpaueb/bert-base-greek-uncased-v1 tokenizer, specifically designed for Greek language processing.

3.2 Text Normalization Process:
a) Unicode Normalization: Applied NFD (Canonical Decomposition) to decompose Greek characters with diacritical marks
b) Accent Removal: Eliminated diacritical marks (category 'Mn') to standardize text representation
c) Case Normalization: Converted all text to lowercase for consistent processing
d) Whitespace Standardization: Removed excessive whitespace and normalized spacing patterns

3.3 Implementation:
The strip_accents_and_lowercase() function performed Unicode normalization by removing combining marks while preserving base characters, followed by lowercase conversion. The preprocess_text() function applied this normalization along with regex-based whitespace cleaning (pattern: r'\s+').

4. ASPECT DETECTION AND SENTIMENT EXTRACTION

4.1 Aspect-Sentiment Extraction:
For each review, the extract_rated_aspects() function processed the eight aspect columns to identify aspects with valid sentiment ratings. Only aspects with explicit ratings ('-1', '0', '1') were retained, effectively filtering out non-applicable aspects marked with '-'.

4.2 Sentiment Encoding:
Sentiment values were transformed into categorical format:
- Negative (-1) → sentiment_id: 0
- Neutral (0) → sentiment_id: 1  
- Positive (1) → sentiment_id: 2

4.3 Aspect Term Localization:
The find_aspect_terms_in_text() function implemented a two-stage aspect detection mechanism:

Stage 1 - Direct Aspect Name Matching:
- Searched for exact matches of preprocessed aspect names within the review text
- Applied character-level position mapping to identify aspect spans

Stage 2 - Keyword-Based Detection:
- Utilized aspect_keywords_map.json (for 'reviews' column) and aspect_keywords_lemma.json (for 'text_lemma' column) containing predefined keywords for each aspect category
- Implemented standalone word boundary detection to avoid partial word matches
- Applied minimum keyword length filtering (≥3 characters) to reduce noise

5. DATA NOISE REDUCTION

5.1 Aspect-Text Alignment Filtering:
A critical denoising step was implemented to ensure data quality for aspect detection tasks. The pipeline filtered out sentiment ratings for aspects that were not explicitly mentioned in the review text, addressing the following issues:

- Removed phantom aspects: Sentiment ratings for aspects not mentioned in the review text
- Retained only verifiable aspect-sentiment pairs where the aspect term was detected within the review content
- Applied this filtering to both original reviews and lemmatized text versions

5.2 Empty Sample Filtering:
Reviews containing no detectable aspects with sentiment ratings were excluded from the final dataset, as these samples would not contribute meaningfully to either aspect detection or sentiment classification training.

6. DATA STRUCTURE TRANSFORMATION

6.1 Output Format:
Each processed review was transformed into a structured JSON format containing:
- 'text_original': Original review text
- 'text_processed': Preprocessed and normalized text
- 'tokens': BERT tokenization output
- 'aspects_present': Array of detected aspect-sentiment pairs

6.2 Aspect Representation:
Each detected aspect was encoded as:
- 'aspect_category': Original aspect name in Greek
- 'sentiment_id': Numerical sentiment identifier (0, 1, or 2)

7. DATASET PARTITIONING

7.1 Primary Split:
Data was partitioned based on the 'type' column:
- Training set: All samples marked as 'train'
- Test/Validation pool: All samples marked as 'test'

7.2 Validation Set Creation:
The test/validation pool was further divided using stratified random sampling:
- Validation set: 50% of the test pool
- Test set: Remaining 50% of the test pool
- Random state: 1312 for reproducibility

8. DATA AUGMENTATION (OPTIONAL)

8.1 Augmentation Strategy:
To address class imbalance in sentiment distribution, an optional augmentation module was implemented targeting underrepresented sentiment classes (negative and neutral sentiments).

8.2 Back-Translation Methodology:
- Primary Method: Greek → Intermediate Language → Greek translation using Google Translate API
- Intermediate Languages: English and French (selected for translation quality and speed)
- Translation Parameters: Maximum 2 retry attempts with 0.05-second delays between requests
- Fallback Strategy: Simple text modifications when translation fails

8.3 Augmentation Targets:
- Target sentiment classes: Negative (sentiment_id: 0) and Neutral (sentiment_id: 1)
- Multiplication factor: 3× original size for targeted sentiment classes
- Positive sentiment class remained unchanged to maintain balance

8.4 Simple Augmentation Fallback:
When translation services were unavailable, three alternative augmentation methods were employed:
- Method 0: Punctuation addition
- Method 1: Word duplication at random positions
- Method 2: Adjacent word position swapping

9. OUTPUT GENERATION

9.1 File Structure:
The pipeline generated datasets in JSON Lines format for both standard and augmented versions:
- all_data.json: Complete processed dataset
- train_data.json: Training partition
- val_data.json: Validation partition  
- test_data.json: Test partition

9.2 Dual Processing:
The pipeline processed both text variants:
- f_data_bert/: Output for original 'reviews' column
- f_data_bert_lemma/: Output for 'text_lemma' column
- f_data_bert_augmented/: Augmented version of original text (when enabled)
- f_data_bert_lemma_augmented/: Augmented version of lemmatized text (when enabled)

10. QUALITY ASSURANCE

10.1 Filtering Statistics:
The pipeline tracked and reported:
- Total processed entries
- Number of filtered entries (due to missing aspects)
- Final dataset sizes for each partition

10.2 Aspect Detection Validation:
Each aspect-sentiment pair was validated through:
- Keyword presence verification in preprocessed text
- Boundary detection to ensure complete word matches
- Span position mapping for potential future use in token classification tasks

This comprehensive data preparation methodology ensured high-quality, properly formatted datasets suitable for training BERT-based models for aspect detection and sentiment classification tasks on Greek language review data.
