XLM-ROBERTA ASPECT TERM EXTRACTION METHODOLOGY

1. OVERVIEW

The Aspect Term Extraction (ATE) system was implemented using XLM-RoBERTa, a multilingual transformer model, enhanced with a Conditional Random Field (CRF) layer for improved sequence labeling performance. The system was designed to identify and extract aspect terms from Greek language product reviews using the BIO (Begin-Inside-Outside) tagging scheme for sequence labeling.

2. MODEL ARCHITECTURE

2.1 Base Model Selection:
The foundation of the ATE system was built upon xlm-roberta-base, a multilingual variant of RoBERTa trained on 100 languages including Greek. This choice was motivated by:
- Multilingual capabilities suitable for Greek language processing
- Robust performance on sequence labeling tasks
- Pre-trained representations that capture cross-lingual patterns

2.2 Enhanced Architecture Components:

a) XLM-RoBERTa Base Layer:
- Model: xlm-roberta-base transformer
- Parameters: ~270M parameters
- Vocabulary: Multilingual SentencePiece vocabulary
- Maximum Sequence Length: 128 tokens (optimized for efficiency)

b) Token Classification Head:
- Linear layer mapping hidden states to label probabilities
- Output dimensions: 3 classes (O, B-ASP, I-ASP)
- Dropout: 0.3 for both hidden states and attention probabilities

c) Conditional Random Field (CRF) Layer:
The system incorporated a custom CRF implementation to model label dependencies:
- Transition Matrix: 3×3 matrix modeling tag transitions
- Constraint Enforcement: Prevented invalid transitions (e.g., O → I-ASP)
- Viterbi Decoding: Optimal sequence prediction using dynamic programming
- Forward Algorithm: Partition function computation for training

2.3 CRF Implementation Details:

The CRF layer enforced BIO tagging constraints through:
- Transition Penalties: O→I-ASP transitions penalized with -10.0 weight
- Valid Transitions: O→O, O→B-ASP, B-ASP→I-ASP, I-ASP→I-ASP, I-ASP→O
- Loss Computation: Negative log-likelihood using forward-backward algorithm
- Inference: Viterbi algorithm for optimal sequence decoding

3. LABEL ENCODING SCHEME

3.1 BIO Tagging System:
The model employed a three-class BIO encoding:
- O (Outside): Token not part of an aspect term (label_id: 0)
- B-ASP (Begin-Aspect): First token of an aspect term (label_id: 1)
- I-ASP (Inside-Aspect): Continuation token of an aspect term (label_id: 2)

3.2 Label Mapping:
```
ASPECT_LABEL_MAP = {"O": 0, "B-ASP": 1, "I-ASP": 2}
ASPECT_LABEL_MAP_INVERSE = {0: "O", 1: "B-ASP", 2: "I-ASP"}
```

4. TEXT PREPROCESSING AND TOKENIZATION

4.1 Preprocessing Pipeline:
Minimal preprocessing was applied to preserve XLM-RoBERTa's multilingual capabilities:
- Case normalization: Conversion to lowercase
- Whitespace standardization: Regex-based cleaning (pattern: r'\s+')
- Character preservation: No accent removal (unlike BERT-based approach)

4.2 Advanced Token Alignment:
A sophisticated alignment mechanism was implemented to handle subword tokenization:

```
enhanced_align_tokens_and_labels(original_tokens, original_labels, tokenizer)
```

Process:
1. Special token handling: Added <s> and </s> tokens with 'O' labels
2. Subword tokenization: Each original token split into multiple subwords
3. Label propagation rules:
   - First subword inherits original label
   - Subsequent subwords: B-ASP → I-ASP, others maintain original label
4. Length verification: Ensured token-label alignment consistency

4.3 Input Format:
- Maximum sequence length: 128 tokens
- Padding: Applied to maximum length for batch consistency
- Attention masks: Generated for valid token positions
- Label alignment: Synchronized with tokenized input

5. TRAINING CONFIGURATION AND OPTIMIZATION

5.1 Hyperparameter Settings:
- Learning Rate: 5e-5 (default, configurable)
- Batch Size: 16 (default, configurable)
- Number of Epochs: 3 (default, configurable)
- Maximum Sequence Length: 128 tokens
- Gradient Clipping: L2 norm of 1.0

5.2 Optimizer Configuration:
- Optimizer: AdamW with weight decay of 0.01
- Learning Rate Scheduling: Linear warmup + plateau reduction
- Warmup Steps: 10% of total training steps
- Scheduler: get_scheduler with linear warmup

5.3 Advanced Learning Rate Management:
Custom learning rate scheduling implemented through CustomLearningRateSchedulerCallback:
- Metric Monitoring: F1-score on validation set
- Patience: Configurable (default: patience//2 for LR reduction)
- Reduction Factor: 0.6 (more aggressive than BERT-based model)
- Minimum LR: 1e-7
- Early Stopping: Activated after minimum LR reached with extended patience

6. LOSS FUNCTION AND TRAINING PROCEDURE

6.1 CRF Loss Function:
The training employed CRF-specific loss computation:
- Forward Algorithm: Computed partition function Z(x)
- Sequence Score: Calculated score for gold label sequence
- Loss: Negative log-likelihood = log(Z(x)) - score(y_true, x)
- Gradient Flow: Through emission scores and transition parameters

6.2 Training Strategy:
- Evaluation Strategy: Every 100 steps
- Save Strategy: Every 100 steps with best model retention
- Early Stopping: Combined with learning rate reduction
- Checkpoint Management: Latest 3 checkpoints preserved

6.3 Custom Trainer Implementation:
CRFTrainer class extended HuggingFace Trainer:
- Custom loss computation for CRF models
- Specialized prediction step handling CRF decoding
- Support for both training and inference modes

9. COMPLETE ABSA INFERENCE PIPELINE

9.1 ABSAPipeline Architecture:
The complete ABSA system was implemented as a two-stage pipeline combining Aspect Term Extraction (ATE) and Aspect Sentiment Classification (ASC):

Stage 1 - Aspect Term Extraction (ATE):
- Input: Raw Greek text
- Model: XLM-RoBERTa + CRF for sequence labeling
- Processing: BIO tagging to identify aspect term boundaries
- Output: Extracted aspect terms with character positions

Stage 2 - Aspect Sentiment Classification (ASC):
- Input: Original text + extracted aspect pairs
- Model: XLM-RoBERTa for sequence classification
- Processing: Sentiment classification for each detected aspect
- Output: Sentiment predictions with confidence scores

9.2 Detailed Pipeline Flow:

**ATE Component (Stage 1):**
```
Raw Greek Text
    ↓
Minimal Preprocessing (case, whitespace)
    ↓
XLM-RoBERTa Tokenization + Offset Mapping
    ↓
ATE Model Forward Pass (XLM-RoBERTa + CRF)
    ↓
CRF Viterbi Decoding (BIO labels)
    ↓
Character Offset Recovery
    ↓
Extracted Aspect Terms: [(text, start_pos, end_pos)]
```

**ASC Component (Stage 2):**
```
For each extracted aspect term:
    Original Text + Aspect Term
        ↓
    XLM-RoBERTa Tokenization (text-aspect pairs)
        ↓
    ASC Model Forward Pass (XLM-RoBERTa sequence classification)
        ↓
    Softmax + Argmax (sentiment prediction)
        ↓
    Sentiment Label + Confidence Score
```

**Complete Pipeline Flow:**
```
Raw Greek Text
    ↓
ATE: XLM-RoBERTa + CRF → Extracted Aspects
    ↓
For each detected aspect:
    ASC: XLM-RoBERTa → Sentiment Classification
    ↓
Final ABSA Results: [(aspect, sentiment, confidences, positions)]
```

9.4 ASC Integration:
The sentiment classification component processes each extracted aspect:
- Input Format: Text-aspect pairs using [SEP] token separation
- Model Architecture: Standard XLM-RoBERTa sequence classification
- Output Classes: 3 sentiment categories (negative, neutral, positive)
- Confidence Scoring: Softmax probabilities for each prediction

9.5 Final Output Format:
Each complete ABSA result includes:
- aspect: The extracted aspect term string
- sentiment: Predicted sentiment label ('negative', 'neutral', 'positive')
- sentiment_score: ASC model confidence (0-1)
- aspect_score: ATE model confidence (placeholder: 1.0)
- start: Character-level start position of aspect
- end: Character-level end position of aspect

9.6 Pipeline Error Handling:
- Empty Text: Returns empty results with warning
- No Aspects Found: Returns empty list, logs information
- ASC Model Unavailable: Returns aspects with neutral sentiment default
- Translation Errors: Graceful degradation with original text preservation
